# TESTING:测试与验收

## 1. 原则

1. 每条 `BEHAVIOR_SPEC` 规格至少对应一个自动化测试或一条手工验收项,测试名或注释里写条目 ID(如 `fn sel_003_clearing_highlight_keeps_buffer()`)。
2. **先让核心逻辑可以脱离图形界面测试。** `term_core` 不依赖 `gpui`,粘贴处理、键位编码、选区文本提取都应有纯单元测试。
3. 测试失败时修代码,不是改测试。只有确认测试本身写错时才改测试,且必须在汇报中单独说明。
4. Windows 与 Linux 都要能跑测试;平台专属测试用 `#[cfg]` 隔离,并保证另一平台至少能编译。

## 2. 测试层次

| 层次 | 内容 | 位置 |
|---|---|---|
| 单元测试 | 粘贴处理、键位编码、颜色映射、配置解析、选区文本裁剪 | 各 crate 内 `#[cfg(test)]` |
| 终端状态测试 | 向 `Term` 喂入字节序列,断言 Grid 内容、光标、模式位 | `term_core/tests/` |
| 选择缓冲测试 | 对 `SelectionBackend` 的 trait 做 fake 实现,测试 SEL 规则 | `term_core/tests/` |
| 集成测试 | 启动真实 PTY 运行简单命令(`echo`),验证输入输出往返 | `term_core/tests/`,标记为需要 PTY |
| 手工验收 | 图形界面、与其他应用互通、vim/tmux/htop | 下方清单 |

## 3. 必须覆盖的单元测试(最低要求)

**PASTE**
- `\r\n`、`\n`、`\r` 混合输入的规范化结果
- 含 `ESC[201~` 的恶意文本被清除后,输出里只有开头与结尾各一对括号标记
- 非 bracketed 模式下 ESC 也被移除
- 空字符串、超长字符串、仅含控制字符的字符串

**SEL**
- 空选区不覆盖已有选区缓冲(SEL-004)
- 清除高亮不清空选区缓冲(SEL-003)
- `copy_on_select` 开启时两个通道都被写入且内容一致(SEL-008)
- 行尾空格裁剪与软换行处理(SEL-012)

**KEY**
- `Ctrl+字母` 得到 `0x01..0x1a`
- 方向键在 `APP_CURSOR` 开/关下的两种序列(KEY-005)
- `Ctrl+C` 不触发复制(KEY-004)

**MOUSE**
- 鼠标上报开启 + 无 Shift → 事件交给程序
- 鼠标上报开启 + Shift → 终端处理(MOUSE-001/002)

## 4. 手工验收清单

> AI 无法运行图形界面时,在汇报中列出需要用户手工验证的条目,**不得标记为已通过**。

**选区与中键粘贴**
- [ ] SEL-001/002:在本终端选中文本,中键粘贴到同一终端
- [ ] SEL-006(Linux):本终端选中 → 浏览器/文本编辑器中键粘贴;反向亦然
- [ ] SEL-006(Wayland):同上,在 Wayland 会话重测
- [ ] SEL-007(Windows):两个窗口之间选中并中键粘贴
- [ ] SEL-003:选中后点击取消高亮,中键仍可粘贴
- [ ] 选中后 `Ctrl+Shift+C` 复制另一段文本,中键粘贴的仍是选中的那段
- [ ] SEL-009:双击选词、三击选行
- [ ] SEL-013:拖拽出窗口边缘,自动滚动并持续选中

**程序交互**
- [ ] MOUSE-001:vim `:set mouse=a` 下,中键由 vim 处理
- [ ] MOUSE-002:同上,按住 Shift 中键,由终端粘贴
- [ ] tmux 开启鼠标模式下的选区与粘贴
- [ ] htop、less、man 的滚轮行为

**粘贴安全**
- [ ] bash 5 / zsh:粘贴多行文本不会立即执行(PASTE-002)
- [ ] 粘贴含 `ESC[201~` 的文本,不会提前结束括号粘贴(PASTE-004)
- [ ] 关闭 bracketed paste 的程序中粘贴多行,出现确认对话框(PASTE-003)

**渲染与输入**
- [ ] 中日韩宽字符对齐、光标位置正确
- [ ] 窗口缩放后行列数与 `stty size` 一致
- [ ] 中文输入法候选框位于光标处
- [ ] `cat` 一个大文件,界面不卡死、可中断

## 5. CI 要求

- 矩阵:`ubuntu-latest`、`windows-latest`。
- 步骤:`fmt --check` → `clippy -D warnings` → `test --workspace`。
- 额外对另一平台做 `cargo check`,保证 `cfg` 分支不会在某一平台悄悄坏掉。
- 带 PTY 的集成测试在 CI 中如不稳定,单独分组并在汇报里说明,不得直接 `#[ignore]`。
