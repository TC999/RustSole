# LICENSING:许可证与参考规则

> 这是项目的法律风险控制线。本文件不是法律意见;最终许可证选择由项目所有者决定。

## 1. 涉及的项目

| 项目 | 许可证 | 本项目的使用方式 |
|---|---|---|
| Konsole | GPL(请用户核实具体版本条款) | **只参考行为与界面**,不得复制代码 |
| Windows Terminal | MIT | 只参考设计思路;如需复制代码,先问用户 |
| Zed(含 `terminal` / `terminal_view`) | 各 crate 不同,请核实 | 只参考结构与思路;不得整段复制 |
| GPUI | Apache-2.0 | 作为依赖使用 |
| alacritty_terminal | Apache-2.0 | 作为依赖使用 |

## 2. AI 的行为规则

1. **不得粘贴、转写或逐行改写**上述项目的源码。"换个变量名重写同样的逻辑"同样不允许。
2. 允许:根据**公开的行为描述**(文档、用户手册、快捷键列表、实际使用观察)自行设计和实现。
3. 实现某功能前,先用自己的话写出行为要求(即 `BEHAVIOR_SPEC` 条目),再据此实现,而不是对着别人的代码实现。
4. 如果 AI 在上下文中看到了参考项目的源码,在汇报里说明"曾读取过某文件",由用户判断是否需要隔离。
5. 需要新依赖时,在汇报中列出:名称、版本、许可证、用途、替代方案。**未经批准不得加入。**
6. 不得引入许可证为 GPL / AGPL 等强传染性协议的依赖,除非用户明确批准并确认项目许可证。
7. 不得复制没有明确许可证的代码片段(包括论坛、博客、AI 生成示例中的片段)。

## 3. 引用规范

- 参考了某个项目的设计思路时,在注释或文档里写:`参考思路:<项目名>,未复制代码`。
- 第三方资源(字体、图标、配色方案)必须附来源与许可证,放在 `THIRD_PARTY.md`。
